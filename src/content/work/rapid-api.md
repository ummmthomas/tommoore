## The challenge

Developers were using several separate platforms to get an API in front of users, and every hand-off between tools slowed delivery down.

## The solution

A single, consistent workflow that covers every stage of the API lifecycle, from design and testing through to monitoring and publishing.

## My role

I owned the project from concept to implementation, working closely with cross-functional partners across Product and Engineering.

## Product architecture

The existing product grouped features by component rather than by what users were trying to achieve. Remote testing and empathy mapping showed people struggling to move between tasks. Our hypothesis was that a goal-oriented structure would speed up task completion and improve conversion.

## Iterative delivery

We worked in a lean, agile way with staged releases. Small fixes shipped alongside larger planning so Engineering could keep delivering, and handover and flow documentation kept stakeholders aligned.

## A distributed team

The team was spread across San Francisco, Central Europe and Tel Aviv, which meant careful scheduling and clear communication habits.

## Bringing the hub into the IDE

We brought key features into IDEs such as Visual Studio Code with feature parity, so developers could search for and request APIs without leaving their environment.

## Outcomes

- **30% increase in conversion** across user segments after a year of iteration.
- **IDE extensions** had the highest daily active user rate and reached 100k users in the first week.
- The **VS Code extension** was the most popular in the marketplace that month.

## Learnings

- **Be lean.** Form strategic hypotheses when resources are limited.
- **Prioritise impact.** Focus on the highest-value areas and lean on teammates' expertise.
- **Find the balance.** Weigh urgency against rigour.
